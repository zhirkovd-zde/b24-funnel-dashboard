# Воронка продаж — дашборд для Битрикс24 (Вайбкод)

Приложение для портала Битрикс24 на платформе [Битрикс24 Вайбкод](https://vibecode.bitrix24.tech): сводка по стадиям воронки, ключевые показатели, последние сделки и фильтр по периоду. Работает от лица авторизованного пользователя. Описание для проверяющего — [DESCRIPTION.md](DESCRIPTION.md).

## Устройство

```
server.js          HTTP-сервер (Node 24, без зависимостей): статика + /api/bootstrap, /api/dashboard
lib/vibe.js        клиент Vibe API: ключ приложения + токен сессии, повторы при 429/502, сообщения об ошибках
lib/service.js     какие вызовы делать: агрегация по стадиям, batch, кэш справочников
lib/dashboard.js   чистая логика: проверка параметров, фильтры, сводка, показатели
lib/mock.js        выдуманные данные для локального запуска и тестов
public/            интерфейс (HTML, CSS, JS без сборки и без внешних CDN)
deploy/            выкладка на Black Hole и ввод ключей
test/              автотесты (node:test)
```

## Локально

```bash
npm test        # автотесты
npm run dev     # http://localhost:3000 на выдуманных данных, без ключей
```

Сценарии имитации: `MOCK_SCENARIO=nostages|empty|huge|partial|error npm run dev`. В `NODE_ENV=production` имитация не включается.

## Переменные окружения сервера

| Переменная | Обязательна | Что это |
|---|---|---|
| `VIBE_APP_KEY` | да | ключ авторизации приложения `vibe_app_` (скоупы `crm`, `user`, `placement`) |
| `PORT` | нет | задаёт платформа, по умолчанию 3000 |
| `NODE_ENV` | нет | `production` на сервере |

Ключ не хранится в коде и в git. На сервер он попадает либо через `env` выкладки (`deploy.mjs` берёт его из окружения), либо секретом в карточке приложения в кабинете Вайбкод — тогда в `env` его можно не передавать.

## Развёртывание с нуля

1. В кабинете Вайбкод → **Ключи авторизации** → **Создать**: название «Воронка продаж», скоупы Битрикс24 `crm`, `user`, `placement`; скоупы Вайбкод снять. Сохранить ключ в менеджер паролей.
2. **Ключи API** → **Создать**: название «Воронка продаж — деплой», режим «Чтение и запись», единственный скоуп `vibe:infra`, срок 30 дней. Сохранить в менеджер паролей.
3. В PowerShell в папке проекта ввести оба ключа скрытым вводом (в переменные окружения только этой вкладки):
   ```powershell
   . .\deploy\set-keys.ps1
   ```
4. Проверить, что видит платформа, и выложить:
   ```powershell
   node deploy\deploy.mjs check
   node deploy\deploy.mjs deploy
   ```
   Скрипт найдёт или создаст сервер (Black Hole), выложит код с рантаймом `node24`, проверит здоровье, пропишет адрес сервера OAuth-приложению и загрузит иконку. При временных сбоях платформы повторяет выкладку сам. По умолчанию — отдельная машина `b24-funnel-dashboard-vm`; приложение в галактике — `$env:GALAXY = '1'` перед командой.
5. Открыть Битрикс24 → левое меню → «Воронка продаж», подтвердить доступ приложению.
6. Опубликовать для сотрудников портала: `node deploy\deploy.mjs publish`. Чтобы сотрудники могли открыть сервер, владелец выставляет политику доступа «Портал» в карточке сервера (решение принимает человек).

Повторная выкладка — шаги 3–4. Состояние и журнал сервера — `node deploy\deploy.mjs status`. Обезличенный `/v1/me` (тип, `accessMode`, скоупы) — `node deploy\deploy.mjs me`. Доступ одному сотруднику без открытия портала — `node deploy\deploy.mjs grant <ID> "Имя Фамилия"` (политика `NAMED_USERS`).

## Если ключ скомпрометирован

Отозвать ключ в кабинете → выпустить новый с теми же скоупами → повторить шаги 3–4 → проверить раздел «Аналитика» на обращения с незнакомых адресов.
